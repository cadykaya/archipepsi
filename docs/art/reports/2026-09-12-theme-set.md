# The six-theme texture set, described and checked

**Arty**

*2026-09-12. Theme-pack gap 3's unblocked half, prepared against the
existing authority while Production supplies the runtime destination and the
binding contract. Nothing here chooses either, and nothing was copied into
`godot/`.*

---

## What was already true

The set exists and always did: **37 PNGs, six themes, 32 texels/m**, at
`assets/textures/theme/`. Gap 3 is not "the textures are missing" — it is
that they ship nowhere and only the preview tool reads them.

What they did not have was **a description a binder could be written
against**, or anything checking them *as a set* rather than as whatever the
shipped shells happen to use. `check_theme_roles.py` asks whether every
material name on every shell resolves to a role and whether the themes cover
that usage. It is a check about the shells.

## The set is complete against the authority

| | |
| --- | --- |
| required roles (§8.1) | `floor`, `wall`, `trim`, `accent` — **all six themes** |
| `hazard` | **universal.** No theme paints one, which is the owner's 2026-09-10 ruling working: a pack *resolves* it to the shared material and must not re-tint it. A theme that shipped one would be the finding. |
| optional (§8.2) | `ceiling` → all six. `metal`, `glass`, `emissive`, `decal` are unshipped and fall back per the contract. |
| variants | `trim_plain` → all six. `wall_ribbed` → **concrete_facility only**, and it stays a variant. Making it a role would hand every future pack a seventh obligation for one theme's convenience. |

## The description

`assets/textures/theme/THEME_PACK.json`, generated by
`tools/content/verify_theme_set.py` and **regenerating byte-identical or the
check fails** — the `art_budgets.json` pattern, so the description cannot
drift from the set it describes.

It carries what a binder needs and nothing it has to infer: every
theme/role → file, the required roles, the universal ones a pack must not
paint, the §8.2 fallback for each optional role, the variants and what they
fall back to, the texel density, a content hash per texture, and each
texture's measured mean value.

## One thing measured and deliberately not asserted

Every texture's **mean relative luminance** is in the descriptor as data. It
is not a gate, and that is a decision rather than an omission: the palette's
`min_value_separation` governs **adjacent steps within a ramp**, not one role
against another. A rule about role-versus-role separation in the rendered
textures would be one I invented and then enforced, which is how a checker
starts reporting defects the authority does not have — the same mistake as
the envelope tolerance earlier today.

If the owner wants such a rule, the numbers to set it from are already in the
file.

## What is checked

`tools/content/verify_theme_set.py`, in `tools/check_art_current.sh` with
every other standing check:

```
verify-theme-set: 6 theme(s), 37 texture(s), 7 role(s); every required role
                  present or universal, and the description matches.
```

| asserted | |
| --- | --- |
| completeness | every required role in every theme, or universal |
| the universal rule | no theme paints `hazard` |
| no partial roles | a **role** in five themes and missing in one is a hole a binder falls into. A **variant** is exempt, by name. |
| the manifest is true | every file exists, at the pixel size it claims, and the set does not mix texel densities |
| the description | regenerates byte-identical |

Two sabotage tests, both confirmed failing first: a theme given its own
`hazard` texture is named and refused; a required role deleted from one theme
is named with the theme.

## What blocks the rest, and it is not Art

**Where the set lands in `godot/content/`, and the binding contract.** A
binder cannot bind textures the game does not have, and the destination is
not Art's call. When Production names one, the remaining work is the copy —
the set is complete, described, hashed and checked.

Gap 5 (the runtime retheme path) is Production's and unchanged by this.
