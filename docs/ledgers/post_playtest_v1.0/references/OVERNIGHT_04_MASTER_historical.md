## Cross-package evidence and integrity rules

A task has five distinct levels: **declared, constructed, reachable/usable, integrated, verified at the stated scope**. “Named in a generated list,” “the node exists,” “the schema accepts,” “the fixture passes” and “played through the normal path” are not interchangeable. A full-game completion claim must use the level it promises.

Keep evidence classes explicit: standalone scenario; named/sample injection; ordinary offline/fallback composition; recorded provider response; genuine model composition; mock AP; actual supported AP integration. Model access missing is not permission to fake it. A fixture exercising real handlers still has synthetic input; a JSON round trip is not a cold process restart. Preserve real source, Zone and seed identities and disclose re-keying.

Every load-bearing test needs both a meaningful success and a relevant refusal/failure or revert control. Expected values must not all be computed from the implementation table being tested. Refusing a name only after a test monkeypatches its support away does not establish that normal catalogue expansion is safely gated. Where a route walker fails, diagnose the actual path/physics interaction before publishing an “impossible room” verdict. A bounded unsuccessful walk is not a universal impossibility proof.

Drive the real production call site. Countdown behavior cannot be tested only by calling the final attack resolver. Progress is not established by reading an object’s prompt from arbitrary distance. In continuous route cases, no relocation between legs, injected inventory, directly completed flags, deleted required obstacles or removed enemies unless that case is explicitly labelled as a narrower diagnostic. Keep real-AI combat coverage separate from direct projectile construction. Do not claim robotic reaction time proves human fairness.

Compile/import/startup checks must observe actual phase markers and exit status. Zero matches for one error string is not a passing run. Parse errors, script errors, timeouts and missing completion markers must be distinguishable. Capture full unbuffered logs outside tracked source, not filtered tails that hide the first failure. Safely identify only the processes owned by this work; never use a broad kill pattern that may terminate another project or the runner itself.

Use focused compile/affected suites for incremental commits. Use full-frontier verification after coherent integration and before a final candidate claim—not mechanically before every push. Freeze source, schema and any identity-sensitive documents during those runs; another lane may work on an isolated worktree but may not change the tested checkout. Generated fixtures are rebuilt from source. Record whether a post-test difference is a provenance stamp or changed measured content.

Do not weaken clearance or solvability checks, drop branches/Checks, remove adverse sample cases, relabel failing suites or normalize outputs into their own success bands to get green. Real capacity failures may be reported and handled through the existing refusal path; do not claim every supported design must fit every host. Keep old fulfilled investigations closed unless an actual new regression touches them.
